### ПРОМПТ ДЛЯ ВНЕШНЕГО ИИ (СКОПИРОВАТЬ В ДРУГОЙ ИИ)

```markdown
Ты — Senior Python-разработчик и AI-инженер. Мы участвуем в тренировочном дне хакатона и решаем Кейс №01: «Классификатор обращений».

Твоя задача — реализовать проект строго по требованиям организаторов, следуя лучшим практикам чистого кода, отказоустойчивости и простоты сдачи.

---

### 1. ОПИСАНИЕ И ЦЕЛЬ ЗАДАЧИ
Необходимо написать компактный и надежный скрипт, который считывает 5 готовых обращений из текстового файла, классифицирует каждое обращение по одной из трех категорий и генерирует вежливый черновик ответа на русском языке для оператора службы поддержки.

### 2. ВХОДНЫЕ ДАННЫЕ (ФАЙЛ `messages.txt`)
В корне репозитория должен лежать файл `messages.txt` со следующим точным содержимым:
1) Как получить справку о месте учёбы?
2) В столовой очередь, еда холодная.
3) Хочу записаться на консультацию завтра.
4) Пропал Wi-Fi в корпусе B.
5) Где парковка для гостей?

(Скрипт должен корректно парсить строки, даже если в них есть ведущие номера вида "1) ", "1. " или просто сырой текст).

### 3. ТРЕБОВАНИЯ К ВЫХОДНЫМ ДАННЫМ
Для каждого обращения скрипт обязан напечатать:
1. Исходный текст обращения.
2. Категорию — строго одну из трех:
   - `справка` (вопросы о документах, получении справок, расписании, навигации, парковке)
   - `жалоба` (недовольство сервисом, едой, очередями, сбоями Wi-Fi/оборудования)
   - `другое` (запись на консультации, предложения, нестандартные запросы)
3. Один качественный, профессиональный черновик ответа на русском языке от лица службы поддержки / администрации организации.

### 4. АРХИТЕКТУРНЫЕ ТРЕБОВАНИЯ К РЕШЕНИЮ
1. **Zero External Dependencies (Базовый режим):**
   - Скрипт должен работать "из коробки" на стандартной библиотеке Python 3.8+ без необходимости делать `pip install`.
   - Должен быть реализован надежный rule-based классификатор (регулярные выражения / стемминг ключевых слов) + контекстные шаблоны ответов.
2. **Опциональный LLM-режим:**
   - Предусмотреть параметр `--mode llm` и чтение `OPENAI_API_KEY` (через стандартный `urllib.request`), отправляющий структурированный prompt в LLM.
   - Обязателен Graceful Fallback: если ключ отсутствует, квота превышена или нет сети — скрипт не должен падать с трейсом, а обязан автоматически переключиться на правила!
3. **Кроссплатформенность и кодировки:**
   - Обязательная поддержка Windows/Linux/macOS, UTF-8 в консоли (перенастройка `sys.stdout.reconfigure(encoding='utf-8')` для исключения кракозябр в Windows PowerShell/CMD).
4. **Формат вывода:**
   - По умолчанию: красивый читаемый текстовый вывод для жюри.
   - Флаг `--json`: чистый JSON-вывод списка объектов `[{"id": ..., "message": ..., "category": ..., "draft_reply": ...}]`.

### 5. СОСТАВ РЕПОЗИТОРИЯ
- `messages.txt` — 5 контрольных обращений.
- `classifier.py` — основной скрипт.
- `README.md` — ровно на полстраницы: "Как запустить" и "Что получилось" (таблица с результатами).
- `.gitignore` — игнорирование `__pycache__`, `.env` и т.д.
- `requirements.txt` — информация о зависимостях.

### ЧТО ОТ ТЕБЯ ТРЕБУЕТСЯ СЕЙЧАС:
1. Предоставь полный, готовый к запуску код `classifier.py`.
2. Прокомментируй ключевые решения.
```

### Подробные задачи по участникам:

#### 🧑‍💻 УЧАСТНИК №1: Data & AI / Rules Engineer (Логика и контент)
- **Зона ответственности:** Семантика данных, классификация, тексты ответов.
- **Пошаговые шаги:**
  1. Скопировать 5 сообщений из кейса и создать эталонный `messages.txt`.
  2. Определить ключевые слова/регулярные выражения для 3 категорий:
     - `жалоба`: очередь, холодная, Wi-Fi пропал, сломалось, не работает;
     - `справка`: как получить справку, где парковка, расписание;
     - `другое`: запись на консультацию, личные просьбы.
  3. Написать 5 официальных, вежливых черновиков ответов на русском языке с указанием конкретных инструкций (кабинеты, личный кабинет, ИТ-служба).
  4. Сформировать системный промпт для LLM (few-shot примеры или четкий JSON-schema).

#### 🛠️ УЧАСТНИК №2: Backend & CLI Core Developer (Скрипт и архитектура)
- **Зона ответственности:** Исполняемый код, стабильность, кроссплатформенность.
- **Пошаговые шаги:**
  1. Написать каркас `classifier.py` с использованием стандартных библиотек (`re`, `urllib.request`, `argparse`, `json`).
  2. Реализовать парсер файла `messages.txt` (с очисткой нумерации `1)`, `2.` и пустых строк).
  3. Интегрировать логику Участника №1 (правила + вызов LLM API).
  4. Добавить флаги `--json`, `--mode rules|llm`, `--file`.
  5. Обеспечить UTF-8 кодировку в Windows-терминале (`sys.stdout.reconfigure`).

#### 📝 УЧАСТНИК №3: QA, DevOps & Documentation Specialist (Сдача и презентация)
- **Зона ответственности:** Репозиторий, документация, сдача задания, защита.
- **Пошаговые шаги:**
  1. Инициализировать Git-репозиторий (`git init`, `.gitignore`).
  2. Написать лаконичный `README.md` ровно на полстраницы:
     - Краткое описание кейса;
     - Команды запуска в 1 строчку;
     - Таблица «Что получилось» со всеми 5 обращениями, категориями и черновиками.
  3. Провести сквозной тест: запустить скрипт с чистого терминала без виртуальных окружений.
  4. Создать репозиторий на GitHub/GitLab, запушить код и отправить ссылку на платформу хакатона.
