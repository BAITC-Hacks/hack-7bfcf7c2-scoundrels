```markdown

### КРИТЕРИИ СДАЧИ ОТ ОРГАНИЗАТОРОВ ХАКАТОНА:
1. В репозиторий положить файл `messages.txt` — 5 коротких текстов из задания.
2. Скрипт печатает для каждого: категория ("справка" / "жалоба" / "другое") и один черновик ответа на русском.
3. Формат сдачи: публичный репозиторий команды.
4. Обязательный README.md ровно на полстраницы: "как запустить и что получилось".

### КОНТРОЛЬНЫЕ 5 ОБРАЩЕНИЙ:
1) Как получить справку о месте учёбы? -> СПРАВКА
2) В столовой очередь, еда холодная. -> ЖАЛОБА
3) Хочу записаться на консультацию завтра. -> ДРУГОЕ
4) Пропал Wi-Fi в корпусе B. -> ЖАЛОБА
5) Где парковка для гостей? -> СПРАВКА

### МОЯ РОЛЬ В КОМАНДЕ (УЧАСТНИК №3):
Я отвечаю за:
1. Создание и оформление файла `README.md` строго по требованиям хакатона (объем — 0.5 страницы формата А4 / около 250-350 слов):
   - Краткое введение (1-2 предложения);
   - Четкая инструкция запуска в 1 строку (для Windows / Linux / macOS);
   - Наглядная Markdown-таблица «Что получилось» (все 5 обращений, итоговая категория, текст черновика);
   - Ключевые фичи решения (0 зависимостей, fallback, поддержка JSON).
2. Настройку окружения и репозитория:
   - Создание `.gitignore` (исключение `__pycache__`, `.env`, `.venv`);
   - Создание `requirements.txt` (с фиксацией отсутствия внешних зависимостей).
3. Проведение QA-тестирования готового решения Участника №2:
   - Проверка запуска на Windows PowerShell и bash;
   - Проверка работы с флагом `--json`;
   - Проверка поведения при отсутствии файла или пустых строках;
   - Проверка кодировок UTF-8.
4. Git и подготовка к сдаче:
   - Инициализация `git init`, понятные коммиты (`feat: ...`, `docs: ...`);
   - Проверка доступности репозитория перед сдачей ссылки жюри.
5. Подготовка краткого питча (30-60 секунд) для защиты перед экспертами.
```
